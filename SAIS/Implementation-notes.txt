   1. prepare_miscellaneous.py for classification-head/MIL style metrics (calcMetrics)
   2. prepare_miscellaneous.py for prototype metrics (calcNCEMetrics)
3. Both call the same helper prepare_miscellaneous.py, which uses sklearn roc_auc_score.

Why train_auc is nan:
1. roc_auc_score needs at least 2 classes in y_true.
2. If only one class is present in that epoch’s labels, auc computation fails and the code falls back to nan in:
   1. prepare_miscellaneous.py
   2. prepare_miscellaneous.py
3. Important detail: the explicit single-class guard in helper is only applied for inference phases (prepare_miscellaneous.py). In train phase, single-class still bubbles into the try/except and becomes nan.
4. So your line train_acc=1, train_precision=1, train_recall=1 with train_auc=nan is consistent with: all train samples in that epoch belong to one class and model predicted that class perfectly.

Why loss is large while accuracy is 1:
1. Your loss is not the same thing as accuracy thresholding.
2. For Prototypes task, loss is NCE:
   1. Implemented at prepare_miscellaneous.py
   2. Formula: loss = -mean(log(num/den))
3. Accuracy only checks argmax correct. NCE penalizes low confidence even when argmax is correct.
4. With loss 1.972, the implied average target probability is about exp(-1.972) ≈ 0.139. That means predictions can all be correct but still not confident, so high loss + 100% acc can happen.
5. If importance_loss is enabled, an extra term is added during train (perform_training.py), which can further increase train_loss.

Also note how train_loss is averaged:
1. Per-batch loss is scaled by batch size and summed.
2. Then divided by dataset size at epoch end: perform_training.py.
